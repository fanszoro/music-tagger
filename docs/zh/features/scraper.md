# ⚔️ 争议管理

当多个刮削来源对同一音轨返回冲突的元数据时，Music Tagger 会汇总所有候选结果，让你逐字段手动解决冲突。

## 刮削器概览

刮削器在后台运行，同时从多个已配置的来源抓取元数据。

![刮削器](https://raw.githubusercontent.com/fanszoro/music-tagger/v0.5.0/docs/images/scraper.png)

## 冲突产生的原因

以下情况会产生冲突：
- 两个刮削来源对同一字段返回不同的值（如曲目标题大小写、专辑名称）。
- 刮削结果与手动编辑的数据部分重叠。
- 多个专辑版本与同一音频指纹匹配。

## 争议解决工作流程

```
音轨扫描 → 刮削来源 A ─┐
                        ├─→ 冲突检测器 → 争议队列 → 手动仲裁
           刮削来源 B ─┘
```

1. **检测**：刮削任务完成后，系统自动标记各来源存在分歧的字段。
2. **队列**：所有未解决的冲突出现在**争议队列**（左侧导航可访问）。
3. **解决视图**：每张冲突卡片并排展示所有来源的值，逐字段选择你认为正确的值。
4. **历史记录**：所有仲裁记录均被保存，可随时重新打开并修改决定。

## 字段保护

你**手动编辑**过的字段会自动被保护——刮削结果永远不会静默覆盖它们。当刮削建议与受保护字段冲突时，系统会提示你确认或拒绝。

## 使用技巧

- 使用**批量接受**，对所有待处理冲突一键采用置信度最高的来源。
- 通过来源、字段类型或日期过滤队列，优先处理最重要的冲突。
